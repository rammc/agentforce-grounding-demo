Kernbeobachtungen für die Demo

  1. Retrieval-Qualität ist die zentrale Story. B-boosted erreicht 14/15 PASS, B-naive 13/15 mit zwei PARTIAL — das Boosting trennt zuverlässig ID-Varianten (AL-3000 vs. AL-3000-S vs. AL-3000-SX). A liegt bei 12/15.
  2. Topic-Instructions beeinflussen die Antwort-Qualität via API kaum. Schlank → 2 PASS, stark → 3 PASS. Der Unterschied liegt im Rauschen.
  3. Der API-Antwort-Drop kommt aus dem Action-Output-Setting "Show in conversation". Das LLM gibt nur eine Einleitung ("Hier sind die Details ...") aus, weil es davon ausgeht, dass der formattedContent-Block separat im UI gerendert wird.
  4. Im UI ist die Antwort vollständig. Sobald wir den Action-Output mitlesen (Concat-Workaround), erreicht B-boosted 12/15 PASS — das ist die User-Sicht.
  5. Konsequenz: Für eine programmatische Integration (API-only) braucht es entweder das UI-Setting deaktiviert oder einen expliziten Wrapper, der die Action-Outputs aggregiert. Für das interaktive Demo-Erlebnis im Agent-Builder ist B-boosted state-of-the-art.
